# Fantastic.Dev badge

Use the compact badge to identify a Fantastic.Dev project. The generated SVG is vendored here so README rendering does not depend on access to the brand-kit repository or a live badge request.

## Reuse in another repository

Copy `fantastic-dev-badge.svg` and `fantastic-dev-logo.svg` into that repository's `assets/` directory, then paste this Markdown into its root README:

```markdown
[![Fantastic.Dev](assets/fantastic-dev-badge.svg)](https://fantastic.dev)

[A Fantastic.Dev Project](https://fantastic.dev)
```

For a README in another directory, adjust the relative image path. Keep the link to `https://fantastic.dev` and the project note as written.

If the project is MIT-licensed and has a root `LICENSE` file, this optional row adds a matching license badge:

```markdown
[![Fantastic.Dev](assets/fantastic-dev-badge.svg)](https://fantastic.dev) [![MIT license](https://img.shields.io/badge/license-MIT-94C173?style=flat-square&labelColor=0c0e13)](LICENSE)
```

## Source and appearance

`fantastic-dev-logo.svg` is copied unchanged from the official [Fantastic.Dev brand kit](https://github.com/FantasticDevHQ/fantastic-dev-brand-kit), `assets/brand/logo-mark.svg`, at commit `0ce1aebc3e8418d7e59ce171e117cf9793dd2f3a`.

`fantastic-dev-badge.svg` is generated by [Shields.io's static badge endpoint](https://shields.io/badges/static-badge), with the complete official SVG passed as a [base64-encoded custom logo](https://shields.io/docs/logos#custom-logos). It uses `Fantastic.Dev` as the label on `#0c0e13`, `Project` as the message on `#94C173`, and the `flat-square` style. The embedded logo retains the official accent tile, glyph colors and proportions. Do not redraw, recolor or replace the mark with a text approximation.

## Regenerate the badge

When the official mark changes, update the vendored logo from the brand kit and record its source commit above. From the repository root, run:

```sh
node --input-type=module <<'NODE'
import { readFile, writeFile } from "node:fs/promises";

const logo = await readFile("assets/fantastic-dev-logo.svg");
const url = new URL("https://img.shields.io/badge/Fantastic.Dev-Project-94C173.svg");
url.searchParams.set("style", "flat-square");
url.searchParams.set("labelColor", "0c0e13");
url.searchParams.set("logo", `data:image/svg+xml;base64,${logo.toString("base64")}`);
const response = await fetch(url);
if (!response.ok || !response.headers.get("content-type")?.includes("image/svg+xml")) {
  throw new Error(`Badge generation failed: HTTP ${response.status}`);
}
await writeFile("assets/fantastic-dev-badge.svg", await response.text());
NODE
```

The custom logo is embedded in the generated badge. Consumers need only the vendored files; the long custom-logo request URL is not required in their README.
